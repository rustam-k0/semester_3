Beuth Hochschule für Technik Berlin – University of Applied Sciences   11
Logging
•   Zur Analyse vom Programmablauf kann neben Debugging auch
    Logging verwendet werden
•   Häufig wird console.log für Logging verwendet
•   Console.log hat mehrere Nachteile
    • Kein Ein- und Ausschalten von Logs
    • Keine Anpassung der Log-Ausgaben möglich
    • In Produktiv-Systemen beeinträchtigen Konsole-Ausgaben die
      Performance
•   Besser ist Verwendung von Logging-Bibliothek/ -Framework




           Beuth Hochschule für Technik Berlin – University of Applied Sciences   12
Winston
•   Im JavaScript-Bereich sehr verbreitete Logging-Bibliothek
•   Installation: „npm install winston“
•   Konfiguration über TypeScript-Datei
    • Definition von Log-Channels (Konsole, E-Mail, etc.)
    • Definition von Ausgabeformat
    • Anpassung von Log-Level an Umgebung (dev, prod, etc.)
•   Logger muss aus Konfigurationsdatei importiert werden

Beuth Hochschule für Technik Berlin – University of Applied Sciences   15
Statische Code Analyse
•        Sehr hilfreich, um Fehler und schlechten Code automatisch zu finden
•        Erhöht Qualität des Programm-Codes deutlich!
•        Gängiges Tool im JavaScript-Umfeld: ESLint
•        Verwendung
         • Installation von notwendigen Modulen (eslint, eslint/js, etc.)

    npm install --save-dev eslint @eslint/js @typescript-eslint/parser @typescript-
    eslint/eslint-plugin

     •    Konfigurationsdatei eslint.config.js hinzufügen
     •    Bei Bedarf Skripte hinzufügen (lint: eslint .)
     •    Test, ob alles ok ist: npx eslint .

 Bootstrap: Einbinden
 Empfehlung
 • Legen Sie alle verwendeten CSS- und JavaScript-Dateien immer auf dem
   eigenen Server ab
 • Einbinden von CSS- und anderen Dateien von anderen Servern
   datenschutzrechtliche problematisch
 • Beim Abruf der Dateien können Anbieter Zugriffe loggen → Verstößt z.T.
   gegen DSGVO
